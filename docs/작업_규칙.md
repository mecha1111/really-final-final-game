# 작업 규칙

AI 코딩 에이전트에게 작업을 시킬 때 **매번 프롬프트에 넣는** 규율.
이 프로젝트에서 실제로 여러 번 사고를 막았다.

새 도구로 옮길 때는 이 문서를 통째로 붙여넣거나, 아래 「프롬프트 템플릿」을 쓴다.

---

## 왜 이게 필요한가 — 실제로 잡은 것들

| 사고 | 무엇이 잡았나 |
|---|---|
| 구글 시트가 옛 quota를 계속 서빙 → 타이틀에 5초만 있어도 조용히 원복 | **조사 단계** |
| clone 분열 자식이 상한 3개를 전부 우회 (400판 중 95%에서 초과) | **실측 검증** |
| 버튼이 간헐적으로 안 눌림 | **추정 금지, 원인부터** |
| 튜토리얼 설계의 전제 두 개가 코드와 반대 | **전제 반박** |
| 시체 게이트 수정이 초심자 1구간을 반토막 | **조정 전/후 비교** |
| 도감 그리드가 실제로는 겹쳐 있었음 (코드상으로는 문제없어 보였음) | **스크린샷 눈 확인** |

---

## 1. 조사 먼저

**코드를 고치기 전에 현행 상태를 조사해 보고하게 한다.**

```
═══ 0. 조사 (수정 금지) ═══
- (확인할 항목들)
표로 보고. 아래 설계와 어긋나는 전제가 있으면 구현 전에 반박할 것.
```

에이전트에게 **전제를 반박할 권한을 명시적으로 준다.** 이게 이 프로젝트의 핵심이다.
지시가 틀렸을 때 그대로 구현하면 잘못된 것이 만들어진다.

실제로 반박이 맞았던 사례가 여러 번 있다 — 지시서가 두 축(마릿수 / 종류 수)을 섞어 읽고 있었다든가, "커서가 반전에 딸려간다"는 전제가 사실이 아니었다든가.

---

## 2. 추정으로 고치지 않는다

```
- 원인부터 규명해 보고할 것. 추정으로 고치지 말 것
- 의심 지점: (짚이는 곳을 나열)
- 원인 확인 후 수정
```

버튼 씹힘의 원인은 `syncButton()`이 매 프레임 `textContent`를 무조건 다시 쓴 것이었다.
추정으로 z-index나 pointer-events를 만졌으면 못 찾았다.

---

## 3. 검증은 실물로

```
- Playwright 실제 마우스 클릭(page.mouse)만 사용. .click() / dispatchEvent 금지
- 1280×720 / 1440×900 / 1920×1080 세 해상도
- 스크린샷으로 눈으로 확인할 것. 코드상 문제없음으로 판정하지 말 것
```

`.click()`은 실제로 눌리지 않는 상태에서도 성공한다.
그리고 **"코드상 문제없음"으로 판정해서 놓친 적이 있다** — 도감 그리드가 그랬다.

헤드리스 fps 측정은 무의미하다(양쪽 다 vsync 상한에 걸린다). 쓰지 말 것.

---

## 4. 커밋 분리

```
- 커밋 N개로 분리
- 작업트리 깨끗
- npm run build 매 커밋 전 통과
```

**각 커밋은 그 자체로 동작해야 한다.**
게이팅과 흐름 전환을 다른 커밋으로 나눴다면, 앞 커밋만 적용된 상태는 깨진 게임이다.
그런 경우는 같은 커밋에 넣는다.

---

## 5. 디버그 플래그

```
- config.debug.enabled는 검증 후 반드시 false로 원복
- 원복이 커밋에 섞이지 않았는지 git diff로 확인
```

검증하려면 켜야 하지만, 켜진 채로 배포되면 심사위원이 D키로 구간점프 패널을 본다.
실제로 임시 커밋 하나가 그대로 라이브에 나간 적이 있다.

---

## 6. 기존 패턴 재사용

```
- 새 스타일/새 컴포넌트를 만들지 말 것. 기존 것을 가져다 쓴다
- 같은 일을 하는 함수가 이미 있으면 그것을 쓴다
```

이 저장소는 같은 판정 기준이 여러 곳에 흩어지는 것을 싫어한다.
`countsForConcurrency` 하나를 고쳤더니 스폰 게이트와 분열 클램프가 자동으로 따라온 것이 좋은 예다.

```

## 코드 규칙 (이 저장소 고유)

이건 「디자인 기준서」에도 있지만, 자주 어겨지는 것만 다시 적는다.

- `filter` / `backdrop-filter` / `drop-shadow` 금지
- `setTimeout` 금지. `dt` 누적으로 처리
- `hidden` 속성 대신 `.on` 클래스 토글
- `vh` 금지. px 고정
- `#desktop`은 transform으로 축소된다. 좌표는 `rect ÷ 배율`. `offsetLeft` 사슬은 대상 자신의 transform을 못 본다
- 캔버스 대상은 논리 x/y가 아니라 그리기 좌표 `drawX/drawY`
- 오버레이는 `#desktop` 안의 `absolute` 형제. `position:fixed` 금지
- 새 UI는 `docs/xp-design-system.html`에 먼저 추가하고 게임으로 옮긴다
- 매 프레임 `textContent`/`style.*`를 무조건 다시 쓰지 말 것 (변경 감지 필수) — 클릭이 씹힌다

- (내용)
★(절대 어기면 안 되는 것은 ★로 표시)

═══ 커밋 2 — (제목) ═══
- (내용)

═══ 검증 ═══

- 1280×720 / 1440×900 / 1920×1080

- config.debug.enabled = false 원복 확인
```

## 안티패턴 — 하지 말 것

**목표 숫자를 쫓아 측정을 반복하는 것.**
"손익분기 여유를 양수로" 같은 목표로 재측정을 다섯 번 돌렸다. 시뮬레이터 안에서만 의미 있는 숫자였고 플레이 체감과 무관했다. 어느 시점에는 끊고 실제로 플레이해야 한다.

**정합성을 이유로 우연히 굴러가던 장치를 지우는 것.**
"상한은 살아있는 수를 세는 게 맞다"는 논리로 시체 스로틀을 지웠더니 초심자 1구간이 반토막 났다. 고치기 전에 그것이 무엇을 지탱하고 있었는지 본다.

**한 번에 여러 파일을 병렬로 작업하는 것.**
같은 파일을 건드리는 작업은 순차로. 튜토리얼과 로딩 연출이 같은 `gameOpening.js`라 순서를 지켰다.
